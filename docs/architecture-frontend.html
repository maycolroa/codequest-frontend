01 · Overview

Frontend de Code Quest 2026

SPA que convierte el catálogo de cursos de DevTalles en un universo explorable. El usuario inicia sesión con Discord, responde un assessment de 4 pasos y recorre sus rutas de aprendizaje sobre un mapa galáctico 3D en WebGL, donde cada curso es un planeta y cada ruta una galaxia.

React 18.3 TypeScript 5.7 Vite 5.4 Three.js 0.186 Tailwind CSS 3.4 React Router 6.28 Zustand 4.5 Docker + Nginx
9rutas en React Router
6módulos en lib/galaxy
7texturas procedurales de planeta
2 500estrellas en el fondo 3D

Qué hace la aplicación

  • Login con Discord vía OAuth2 del backend; el JWT llega como ?token= y se captura en cualquier ruta.
  • Assessment de 4 pasos (intereses, nivel, objetivos, tecnologías) que personaliza el mapa.
  • Mapa galáctico 3D con Three.js: planetas por curso, nebulosas por galaxia y líneas de prerrequisitos.
  • Bitácora (dashboard) con progreso, racha de 28 días y efecto warp en canvas 2D.
  • Devi, asistente flotante disponible en todas las rutas protegidas.

Levantar en local

Instalar dependencias

npm install

Requiere Node 20+ (la misma versión que usa el Dockerfile).

Configurar el entorno

cp .env.example .env

VITE_MOCK_MODE=true para trabajar sin backend; false y VITE_API_URL apuntando a localhost:3000/api/v1 para usar el real.

Arrancar Vite

npm run dev

Sirve en http://localhost:5173 con strictPort: si el puerto está ocupado, falla en lugar de cambiar de puerto.

03 · Arquitectura

Estructura de src/

Las páginas orquestan; los hooks encapsulan efectos y estado local; lib/galaxy reúne la lógica 3D reutilizable y testeable; services y stores son la única vía hacia el backend.

Arranque de la aplicación

index.html main.tsx <StrictMode> + <Toaster theme="dark"> App.tsx · BrowserRouter TokenRedirectHandler Routes

ProtectedRoutes

src/App.tsx

Si hay token pero no usuario, llama a fetchMe() y muestra «Validando sesión...». Autenticado: renderiza <Outlet /> más <DeviChat />. Sin sesión: Navigate a /login.

TokenRedirectHandler

src/App.tsx

En cualquier ruta salvo /auth/callback, lee ?token=, lo quita de la URL con history.replaceState, lo guarda en el store y navega a /dashboard (o a /login si fetchMe falla).

04 · Galaxy 3D

El mapa galáctico

StarMap3D (ruta /starmap, cargado con lazy) obtiene galaxias y cursos con useCourseGalaxy, filtra por búsqueda y nivel, y entrega todo a useGalaxyScene. El hook monta una escena Three.js imperativa sobre un <canvas> y se comunica con React sólo mediante callbacks y refs.

StarMap3D.tsx useCourseGalaxy useGalaxyScene planetVisuals · relationLines · galaxyHighlight WebGLRenderer

Patrones de superficie por galaxia

Vista previa aproximada de los patrones que planetVisuals.ts pinta en canvas 2D. Se generan en escala de grises y el color de la galaxia se aplica en el material; aquí se tiñen sólo para distinguirlos. noise es el fallback para galaxias sin patrón asignado.

06 · CI/CD

De main a producción

Workflow .github/workflows/deploy.yml («Build & Deploy Frontend»). Cada push a main construye la imagen Docker con la URL del backend incrustada y la sube al Container Registry de DigitalOcean con dos tags.

01 · trigger

Push a main

on.push.branches: [main], incluido el merge de un PR.

02 · runner

GitHub Actions

ubuntu-latest: checkout, instala doctl y hace doctl registry login con DIGITALOCEAN_ACCESS_TOKEN.

03 · build

docker build

--build-arg VITE_API_URL=${{ secrets.VITE_API_URL }}; Vite incrusta la URL en el bundle.

04 · registry

docker push

registry.digitalocean.com/codequest/frontend con tags :latest y :${{ github.sha }}.

05 · deploy

App Platform

Autodeploy al detectar la nueva imagen :latest en el registry.

NotaEl workflow termina en el docker push: no contiene un paso de deploy. El despliegue depende de que la app de App Platform tenga activado el autodeploy de la imagen :latest (deploy_on_push), por eso la etapa 05 aparece con borde discontinuo. El README todavía describe un despliegue como Static Site, que ya no coincide con este flujo.

Imagen Docker multi-stage

# Stage 1 · build
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
ARG VITE_API_URL
ENV VITE_API_URL=$VITE_API_URL
RUN npm run build   # tsc -b && vite build
# Stage 2 · runtime
FROM nginx:1.27-alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

# nginx.conf: try_files $uri $uri/ /index.html
# assets estáticos: expires 1y, Cache-Control immutable, gzip

07 · Variables de entorno

VITE_API_URL y compañía

Vite reemplaza import.meta.env.VITE_* por su valor literal en tiempo de build. El contenedor final sólo sirve archivos estáticos con Nginx, así que cambiar la URL del backend exige reconstruir la imagen: no basta con una variable de entorno en runtime.

VariableLocal (.env.example)ProducciónSe usa en
VITE_API_URLhttp://localhost:3000/api/v1Secret VITE_API_URL de GitHub → --build-argservices/api.ts (baseURL de Axios, timeout 30 s) y services/auth.service.ts (redirect a /auth/discord)
VITE_MOCK_MODEtrueNo se pasa en el build → undefined → modo realuseCourseGalaxy, auth.store, LoginPage, paths.service, assessments.service
VITE_APP_NAMECode Quest 2026No se pasa en el buildDeclarada en .env.example; hoy no se lee desde src/

Cómo llega VITE_API_URL al bundle

1 · GitHub secret

secrets.VITE_API_URL en el repositorio.

2 · build-arg

docker build --build-arg VITE_API_URL=… en el workflow.

3 · ARG → ENV

El stage build la expone como variable de entorno para npm run build.

4 · Vite

Reemplaza import.meta.env.VITE_API_URL por el string literal en dist/assets/*.js.

Build manual

docker build \
  --build-arg VITE_API_URL=http://localhost:3000/api/v1 \
  -t codequest-frontend .

docker run -p 8080:80 codequest-frontend   # http://localhost:8080
OjoCualquier valor VITE_* queda visible en el JavaScript público. No guardes secretos en estas variables.
